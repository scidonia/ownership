\begin{abstract}
Reference counting makes an array update in place exactly when the array's
count is one; under any other count the update copies. We ask whether a static
discipline can turn that runtime condition into a guarantee for a fragment of
Lean~4's compiler, without changing the host language's type system. The
development is a shallow embedding: a model heap with counts, a decidable
checker whose soundness is proved in Lean, strict recognisers for the emitted
array-write prefixes, and a correspondence between the recognised LCNF and the
model. We derive the temporary pair's count accounting and the put-back's
exclusive branch, build a concrete runtime model in which the exclusivity check
cannot abort under the correspondence, and bind the result to the pinned
toolchain with an artifact/IR/C gate and a differential corpus. The boundary is
explicit: the C runtime's semantics, replay-to-backend identity, the emitted
recursive callee and the source correspondence remain assumptions or open
obligations.
\end{abstract}

\section{Introduction}
Reference-counted functional languages such as Lean~4 and Koka update a shared
array by copying it and leave the in-place branch to the runtime's exclusivity
test \cite{lean4,perceus,countingbeans}. The resulting cost is data-dependent and
invisible in the type: the same source program can copy or not depending on how
many references happen to exist at the write. A static discipline that guarantees
the count is one at the write would make the in-place branch a property of the
program rather than of its current heap, and would let a library or a compiler
rule out the copy branch without a dynamic test.

The difficulty is that Lean~4 has no linear, affine or uniqueness types, and
adding them would change the kernel, the elaborator and every library. The
development therefore does not extend the source type system. It states the
count-one property over the compiler's own LCNF, checks it with an ordinary Lean
function, and proves that the checked fragment corresponds to a model in which
the write is exclusive.
The paper makes five contributions. (i) A model heap and a decidable checker
whose soundness is a Lean theorem (\Cref{thm:check-sound}); an entry invariant
supplies the heap facts the checker cannot see (\Cref{thm:entry-inv}).
(ii) Strict recognisers for the emitted array-write prefixes, with structural
rejection of token-preserving near misses. (iii) A correspondence from the
recognised LCNF to the model (\Cref{thm:prefix-sound} and \Cref{thm:path-sound}), including
the finite nested path. (iv) A counted extraction/call/restoration argument
(\Cref{thm:pair} and \Cref{thm:putback}). (v) A concrete runtime model and an
abort-impossibility theorem (\Cref{thm:no-abort}), bound to the pinned toolchain
by a gate and a differential corpus.

Nothing in the development changes Lean's kernel, elaborator or set of type
formers. The discipline is a shallow embedding: \lean{Ctx}, \lean{Heap},
\lean{check}, \lean{run} and their theorems are ordinary Lean definitions; the
source programs are \lean{Code}/\lean{NCode} values or recognised LCNF. A new
linear type former would require changing the kernel, unification and every
library; the checker avoids that. The price is that linearity is a checked
property of a recognised fragment under named contracts rather than a typing
judgement for all programs. We state that boundary explicitly.

\section{Setting: Lean 4, LCNF, and reference counting}
Lean~4 compiles through a sequence of IRs. The last LCNF phase inserts
reference-count operations, and the backend emits C. The runtime decides an array
update with \lean{lean\_is\_exclusive}: count one and non-persistent means in
place; every other case copies. The development pins the toolchain, the sibling
revision and the captured LCNF artifacts, so every claim names the code it is
about.
The problem is not to implement reference counting, but to know statically that
the count at a particular write is one. Lean's source type system has no
linearity or uniqueness; adding one would be a language change. We therefore
state the property over the compiler's code and prove the connection, rather
than extend the type system.

\section{The ownership discipline}

\subsection{The judgement and its rules}
A context records, for each variable, whether it is owned, borrowed, scalar or
dead, which reference it denotes, and the multiplicity of that reference. The
checker is a total function from a context and a program to a successor context
or failure; the frame stack records open extractions. The rules in
Table~\ref{tab:rules} are ownership obligations: a write is admitted only for an
owned handle of multiplicity one, an extraction only with the frame discipline,
and a call only with an isolated body that returns the state it was handed.

\centering
\small
\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash}p{3.3cm}>{\raggedright\arraybackslash}p{6.4cm}>{\raggedright\arraybackslash}X@{}}
\toprule
Rule & Obligation & Effect \\
\midrule
\lean{let x (checkAlias a)} & \lean{a} owned, multiplicity one & \lean{x} is the checked alias \\
\lean{setArr x i v} & \lean{x} owned, multiplicity one; \lean{i}, \lean{v} scalar & exclusive write through \lean{x} \\
\lean{inc x n}, \lean{dec x n} & \lean{x} owned & multiplicity $\pm n$; \lean{dec} erases \\
\lean{takeOut a i fst snd e} & \lean{a} owned, multiplicity one; \lean{i} scalar; \lean{e} multiplicity one; \lean{fst}, \lean{snd} dead and distinct; \lean{e ≠ a}; no open frame at \lean{a} & push the frame; bind parent and element \\

\bottomrule
\end{tabularx}

\label{tab:rules}
\end{table}

The frame stack is the local form of the ownership invariant. An extraction
opens a frame naming the array, index and element; a put-back closes the matching
frame; a call checks its body under an isolated context and continues with the
result. The exit rule is deliberately conservative: with one open frame only the
extracted element may return, and a deeper stack must be restored first. These
are the rules that make nested updates safe, and they are exactly the parts a
source-level linear type system would encode in types; here they are a checker.

The checker sees the shape of the context, not the heap: slot contents, counts,
client separation and root completeness are supplied by \lean{Inv} and
\lean{EntryInv}, and by the fixture's heap.

\subsection{Worked examples}
Each example is a \lean{Code} or \lean{NCode} value; the \lean{\#guard} is the
executable check, and the surrounding context and heap are the repository's
fixtures. The first two isolate the write rule; the next two the frame stack;
the last two the call's isolation.

\needspace{10\baselineskip}\begin{example}[A unique write]\label{ex:unique}\end{example}
\begin{minted}{lean4}
def execSet (x y i v : Var) : Code :=
  .let y (.checkAlias x) (.setArr y i v (.ret y))

#guard (check (initCtx 0) (execSet 0 3 1 2)).isSome
\end{minted}

\needspace{10\baselineskip}\begin{example}[An aliased write is refused]\label{ex:alias}\end{example}
\begin{minted}{lean4}
def aliasSet (x y i v : Var) : Code :=
  .inc x 1 (execSet x y i v)

#guard (check (initCtx 0) (aliasSet 0 3 1 2)).isNone
\end{minted}
The alias increments the handle, so the write's multiplicity-one obligation
fails; the same refusal appears at the context level for a heap whose count is
two. This is the static counterpart of the runtime copy: the checker rejects the
program before it can copy.

\needspace{10\baselineskip}\begin{example}[An extraction and its return]\label{ex:takeout}\end{example}
\begin{minted}{lean4}
def good : NCode :=
  .takeOut 0 1 2 3 1 (.ret 3)

#guard (checkN ctx0 good).isSome
\end{minted}

\needspace{10\baselineskip}\begin{example}[A stale slot is refused]\label{ex:stale}\end{example}
\begin{minted}{lean4}
def bad : NCode :=
  .takeOut 0 1 2 3 1 (.takeOut 2 1 4 5 1 (.ret 5))

#guard (checkN ctx0 bad).isNone
\end{minted}
The second extraction reopens the array whose slot the first has already
emptied. The frame stack records the first extraction, so the second is refused;
the runtime would fault at that point, which the fixture also checks.

\needspace{10\baselineskip}\begin{example}[A recursive body confined to its state]\label{ex:call}\end{example}
\begin{minted}{lean4}
def good : NCode :=
  .takeOut 0 1 2 3 1
    (.callAt 3 4 7 9 (.ret 3) (.ret 9))

#guard (checkN ctx0 good).isSome
\end{minted}

\needspace{10\baselineskip}\begin{example}[A suspended parent is refused]\label{ex:suspended}\end{example}
\begin{minted}{lean4}
def bad : NCode :=
  .takeOut 0 1 2 3 1
    (.callAt 3 4 7 9
      (.takeOut 2 4 5 6 2 (.putBack 5 6 4 8 (.ret 3)))
      (.ret 9))

#guard (checkN ctx0 bad).isNone
\end{minted}
The refused body returns the call's own state, exactly as the accepted body
does; the difference is isolation. The body runs from an isolated context in
which the suspended parent is dead, so opening it is not a typing error in the
host language but a failure of the checker's ownership obligation.

\subsection{The invariant and soundness}
The model heap, its counts and exclusivity are the semantic side of the
judgement: \lean{Inv} ties the context's multiplicity to the heap count, and
\lean{Exclusive} is count one and non-persistence. The checker's soundness
theorem is the bridge from the static obligation to the heap: every accepted
write selects the exclusive branch. The entry invariant adds the facts a local
checker cannot see: the invariant tree, client separation and root completeness.
For fresh arrays \lean{initEntryInv} establishes it, and
\lean{checkN\_sound\_of\_entryInv} combines it with the checker.

\needspace{10\baselineskip}\begin{claim}[Invariant and exclusivity]\label{def:inv}\end{claim}
\begin{minted}{lean4}
structure Inv (H : Heap) (env : Env) (c : Ctx) : Prop where
  rc_eq         : ∀ r, H.rc r = c.mult r
  owned         : ∀ x r, c.us x = .owned → c.refOf x = some r →
                    env x = some (.ref r) ∧ 1 ≤ c.mult r
  borrow        : ∀ x r, c.us x = .borrow → c.refOf x = some r →
                    env x = some (.ref r) ∧ H.cells r ≠ none
  scalar        : ∀ x, c.us x = .scalar → ∃ n, env x = some (.scalar n)
  nonPersistent : ∀ r o, H.cells r = some o → o.persistent = false
\end{minted}
\begin{minted}{lean4}
def Exclusive (H : Heap) (r : Ref) : Prop :=
  ∃ o, H.cells r = some o ∧ o.rc = 1 ∧ o.persistent = false
\end{minted}

\needspace{10\baselineskip}\begin{claim}[Checker soundness]\label{thm:check-sound}\end{claim}
\begin{minted}{lean4}
theorem check_sound {c : Code} {ctx ctx' : Ctx} {H : Heap} {env : Env}
    (hc : check ctx c = some ctx') (hi : Inv H env ctx) :
    ∃ H' env' v ws,
      run c env H = .done H' env' v ws ∧
      (∀ w ∈ ws, w.2 = true) ∧ Inv H' env' ctx'
\end{minted}

\needspace{10\baselineskip}\begin{claim}[Entry invariant]\label{thm:entry-inv}\end{claim}
\begin{minted}{lean4}
structure EntryInv (H : Heap) (env : Env) (c : Ctx) (root : Ref)
    (client : List Ref) : Prop extends Inv H env c where
  uniqueTree : UniqueTree H root
  separated  : ClientSeparated H root client
  complete   : RootsComplete c H root
\end{minted}
\begin{minted}{lean4}
theorem checkN_sound_of_entryInv
    (hEntry : EntryInv H env c root client)
    (hag : Agrees H env code) (hc : checkN c code = some c') :
    ∃ H' env' v ws,
      runN code env H = .done H' env' v ws ∧
      (∀ w ∈ ws, w.2 = true) ∧ Inv H' env' c'
\end{minted}
\noindent{\small\itshape The quoted signature is the repository's; the heap and environment
parameters are implicit.}

The checker's local rules do not name the heap's path structure. The path theory
supplies it: agreement composes through take-out, call and put-back,
annotation reachability follows the path, and the safety results lift the checker
to every finite path. This is where the per-client proof obligations are
replaced by structural facts.

\section{Recognising the emitted write}
A source-level discipline is only useful if it survives lowering. The compiler
rewrites the program, inlines helpers and chooses the emitted shape; the
recogniser therefore walks the actual LCNF value, pinning operation order,
arities, operand identities and branch constructors. It rejects any
token-preserving near miss, so the correspondence is about the code we name, not
a look-alike.
Three shapes are recognised: the top-level \lean{execP} write, the nested
\lean{setAt} path, and the two \lean{Path.left}/\lean{Path.right} pair arms with
their joins. The pair arms are the test that the recogniser handles control flow
structurally rather than flattening it; the path and the pair carry their own
contracts (A1--A12 and N1--N12), named where they are assumed.

\section{Correspondence to the ownership model}
The checker is about the model, not about the compiler. The bridge executes the
operation trace the recogniser emitted for the actual declaration and proves it
equal to the model run; the recognition hypothesis is load-bearing because
\lean{execAST} returns nothing unless the code decodes to the expected prefix.
The primitive meanings are the named contracts, not theorems about Lean's
backend.

\needspace{10\baselineskip}\begin{claim}[Prefix correspondence]\label{thm:prefix-sound}\end{claim}
\begin{minted}{lean4}
theorem project_sound (assign : FVarId → Var) (p : Prefix)
    (code : Code .impure) (hproj : projectPrefix code = some p)
    (hag : Agrees assign p s env H root i v)
    (hcell : H.cells root = some o) (hin : i < o.fields.size) :
    PrefixOutcome.ofExec assign p (execAST assign p code s) =
      some (PrefixOutcome.ofModel (Ownership.run (p.toModel assign) env H))
\end{minted}
\noindent{\small\itshape The layout and the heap/environment parameters are implicit, as in the
repository.}

\needspace{10\baselineskip}\begin{claim}[The write is in place]\label{thm:prefix-in-place}\end{claim}
\begin{minted}{lean4}
theorem recognized_write_in_place
    (hproj : projectPrefix code = some p) (hl : Layout assign p)
    (hEntry : EntryInv H env (Runner.initCtx root) root client)
    (hag : Agrees assign p s env H root i v)
    (hcell : H.cells root = some o) (hin : i < o.fields.size) :
    PrefixOutcome.ofExec assign p (execAST assign p code s) =
        some (inPlaceOutcome root i v o H) ∧
    PrefixOutcome.ofModel (Ownership.run (p.toModel assign) env H) =
        inPlaceOutcome root i v o H
\end{minted}
\noindent{\small\itshape The machine, environment and heap are implicit.

The nested path is where a finite model meets recursive code. The model nests
take-out, call and put-back per level; the finite-path induction discharges the
callee contract from the tail and leaves only the leaf contract and the emitted
call's meaning (N10). The model's flat environment cannot express the emitted
per-invocation \lean{oproj[1]} index; that bound is recorded rather than hidden.

\needspace{10\baselineskip}\begin{claim}[Nested finite path]\label{thm:path-sound}\end{claim}
\begin{minted}{lean4}
theorem index_path_simulates_model
    (declName takeOut : Name) (assign : FVarId → Ownership.Var)
    (p : NestedPrefix) (code : Code .impure)
    (hproj : projectNested declName takeOut code = some p)
    (ls : List Level) :
    NestedOutcome.ofExec assign p
        (execNestedAST declName takeOut assign body p code s) =
      NestedOutcome.ofModel (Nested.runN (build path value body ls) mEnv H) ∧
    ∃ H' env' ws,
      Nested.runN (build path value body ls) mEnv H =
        .done H' env' (.ref rA) ws ∧ (∀ w ∈ ws, w.2 = true)
\end{minted}
\noindent{\small\itshape The level facts, agreement and entry state are implicit; the leaf
contract is the remaining supplied premise.}

\needspace{10\baselineskip}\begin{claim}[The finite nest]\label{thm:finite}\end{claim}
\begin{minted}{lean4}
theorem calls_build (path value : Var) (body : NCode) (ls : List Level) :
    calls (build path value body ls) = calls body + ls.length
\end{minted}
\begin{minted}{lean4}
theorem callBody_build (path value : Var) (body : NCode) (l : Level)
    (rest : List Level) :
    callBody? (build path value body (l :: rest)) =
      some (build path value body rest)
\end{minted}

\section{Counted extraction, call, and restoration}
The emitted take-out creates a pair whose fields are the parent and the
extracted child. The constructor moves the handles into the pair; the
projections increment them; freeing the unique pair releases both edges. The
counts are therefore equal at the boundary, but only because the pair is freed:
the negative controls show that omitting the free, or retaining an alias, leaves
a count of two. Without this accounting, N2's neutrality would be a modeling
premise rather than a derived fact.

\needspace{10\baselineskip}\begin{claim}[Pair accounting]\label{thm:pair}\end{claim}
\begin{minted}{lean4}
theorem pair_accounting {H : Heap} {p c : Ref} {i : Nat}
    (hw : WellFormedEntry H p c i) :
    let B := protocol H p c i
    B.2.rc p = 1 ∧ B.2.rc c = 1 ∧
      B.2.cells p ≠ none ∧ B.2.cells c ≠ none ∧
      B.2.cells B.1 = none ∧
      Heap.Exclusive B.2 p ∧ Heap.Exclusive B.2 c ∧
      B.2.rc p = H.rc p ∧ B.2.rc c = H.rc c
\end{minted}
\begin{minted}{lean4}
theorem no_free_components_not_exclusive
    (hw : WellFormedEntry H p c i) :
    let B := protocolNoFree H p c i
    B.2.rc p = 2 ∧ B.2.rc c = 2 ∧ ¬ Heap.Exclusive B.2 p
\end{minted}

The put-back is the second place where a copy can hide. The operation has two
dispositions: at count one it mutates the parent; at a higher count or a
persistent parent it allocates a fresh cell and decrements the input. The
exclusive branch is derived from the counted-pair boundary and the child-call
boundary, with functional restoration and count preservation separate; the
returned-handle accounting remains a named premise.

\needspace{10\baselineskip}\begin{claim}[Put-back exclusivity]\label{thm:putback}\end{claim}
\begin{minted}{lean4}
theorem putBack_exclusive_of_wellFormed
    (hw : CountedPair.WellFormedEntry H p c i)
    (hc : ChildCall Hin Hout env ctx state path x body p c) :
    ∃ H',
      putBack H p i c = some (p, H') ∧
      H'.cells p = (mutate H p o i c).cells p ∧
      Heap.Exclusive H' p ∧ H.rc p = 1
\end{minted}
\noindent{\small\itshape The child's admitted body and the returned-handle accounting are implicit;
the conclusion is the exclusive branch and the parent's count.}

\section{Runtime model and abort impossibility}
The model's count is a ghost count; the runtime's is the one that decides. The
runtime model is a separate state machine with its own heap, counts,
persistence, guarded allocator, check and two array-set dispositions. The
structural correspondence preserves refs, cells, counts, persistence, fields and
the cursor; from it the model's exclusivity implies the runtime's, the check
returns, and the write mutates. The abort branch is unreachable under the
correspondence and \lean{EntryInv}.

The definitions are ordinary Lean structures. The correspondence contains no
exclusivity or disposition; those are derived from the preserved counts,
persistence and fields. A guarded allocator refuses a dirty cursor, so the copy
branch cannot overwrite a live cell.

\needspace{10\baselineskip}\begin{claim}[No abort]\label{thm:no-abort}\end{claim}
\begin{minted}{lean4}
theorem checkExclusive_no_abort {H : Heap} {R : RHeap} {r : Ref}
    (hC : Corr H R) (hx : H.Exclusive r) :
    checkExclusive R r = .ok r ∧
      ∀ r', checkExclusive R r ≠ .abort r'
\end{minted}
\begin{minted}{lean4}
theorem setAt_inPlace_of_entryInv
    (hEntry : EntryInv H env (Runner.initCtx root) root client)
    (hC : Corr H R) (hcell : H.cells root = some o)
    (hR : R.cells root = some o') (hin : i < o.fields.size) :
    ∃ H',
      setAt R root i (.scalar vn) = some (.inPlace H' root) ∧
      Corr (inPlaceOutcome root i vn o H).heap H'
\end{minted}

\needspace{10\baselineskip}\begin{claim}[Emitted-semantics abort impossibility]\label{thm:prefix-no-abort}\end{claim}
\begin{minted}{lean4}
def PrefixAborts (out : Option PrefixOutcome) : Prop :=
  ∃ o, out = some o ∧ o.fault ≠ none

theorem prefix_abort_impossible
    (hproj : projectPrefix code = some p)

\section{Empirical alignment}\label{sec:empirical}
The model is only as good as its match to the compiler. A compiled probe compares
the model's predicates with \lean{lean\_is\_exclusive} and address identity on a
corpus: a unique array, a live alias, the alias released before the write, a
persistent literal and a closure-held array. The closed-pure-array case is the
important negative: a pure closed array is lifted to a \lean{\_\_\_closed}
constant read through \lean{lean\_obj\_once}, so it is shared and the write copies
even though the source looks unique. The gate also binds the pinned artifacts,
the IR shapes, the generated C and the runtime header. The corpus is evidence,
not an exhaustive equivalence.

\section{Limits and non-claims}
\needspace{10\baselineskip}\begin{nonclaim}
The boundary is explicit. The C semantics of the primitives is not formalised;
replay-to-backend identity (A10) and address identity remain assumptions; the
emitted recursive callee and continuation (N10) are not captured; the model's
flat environment cannot express the emitted per-invocation index; the leaf body
contract and several heap-shape facts remain supplied; free/cascade, persistence,
concurrency and callbacks are outside the fragment; and the M7 source
correspondence is not attempted.
\end{nonclaim}

Reference counting and reuse: Perceus and Counting Immutable Beans

\section{Conclusion}
The development proves the count-one discipline at the model, the recognised
LCNF and the runtime model, under named contracts; it measures the linked
primitive on a corpus and gates the pinned evidence. What remains is the C
semantics, the replay/backend identity, the emitted callee and the source
correspondence. The next step is either a verified runtime model or a stronger
backend gate; the static discipline itself is complete for the recognised
fragment.
