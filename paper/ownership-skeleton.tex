\begin{abstract}
A reference-counted array update copies whenever the array is shared or persistent,
decided at run time from heap state the source never mentions. We define a
count-one ownership discipline for a fragment of Lean~4's compiler IR and mechanise
it against model semantics. Its foundation is a
complete accounting relation equating each count with the fields that reference the
cell plus the owning variables that denote it, which at count one
forces one owning root with no edge, or one edge with no root. Preservation is
proved for a restricted flat fragment, and separately for the extraction, call and
restoration protocol at its accounted boundaries, since the temporary pair the
emitted code allocates makes the relation false between them. For the recognised
fragment, the counted interpreter's whole run, through restoration and return, is
proved to be heap-compatible with the model run and to agree with it in result,
fault and trace under an explicit counted child-call contract. The result is a
checked count one for that fragment under recognition, layout, entry and call
premises: not a physical count, a step-by-step account in the pair-live window, or
a claim about C.
\end{abstract}

\section{Introduction}\label{sec:intro}

An array update should cost the same whoever else holds the array. In Lean~4 it
does not: arrays are reference counted, and a write mutates in place exactly when
the array is uniquely referenced and not persistent, and otherwise copies the
whole array \cite{lean4,perceus,countingbeans}. Lean's
\lean{lean\_is\_exclusive} makes that decision at run time, from heap state the
source never mentions, so $n$ updates over an $n$-element array can cost linear
or quadratic time according to sharing alone. A static ownership discipline would
make the in-place branch a compile-time guarantee; Lean~4 has no ownership or
linear types, and adding them would be a language change. This paper recovers the
guarantee without one, for a fragment of the compiler's IR, by an external
count-one discipline whose soundness is proved in Lean~4 against model semantics.

The first obstruction is that a count of one is not one owner. The natural
invariant equates the heap's stored count with the context's multiplicity, but
binding a second owned variable leaves that equality true while two variables now
denote the cell; a kernel-checked countermodel (\lean{alias\_not\_accounted})
exhibits exactly that state. The repair is complete accounting: a duplicate-free
support enumerating every owning variable, a domain covering every live cell, and
the equation
$\mathit{rc}(r) = \mathit{IncomingCount}(r) + \mathit{EnvOwnerCount}(r)$, whose
right side counts the heap fields that reference $r$ and the owning variables that
denote it. At count one the equation admits exactly two shapes---one owning root
and no incoming edge, or no owning root and exactly one incoming edge---and two
owning variables at one cell are the same variable. The integer now has a
meaning.

The second obstruction is the emitted code. A nested update takes the element out
of the array, allocates a pair holding parent and child, projects both handles,
frees the pair, calls on the child and puts the result back. At the take-out the
pair's field duplicates the parent reference without raising the count, while the
caller's handle still owns it, so the equation reads one $=$ one plus one; it
becomes true again at entry, after the release and after restoration, and nothing
in between is accounted. The proof is therefore a boundary simulation: count
identities for the pair's traffic, restoration's in-place branch derived from the
protocol and call boundaries, and a compatibility relation that lets the counted
cursor run one ahead of the model's. Closing the fragment needs a modular
boundary. The child call is a contract, and its counted version must also supply
the caller's accounting at the body's return, which the finite-path induction
over model paths does not construct.

We prove, for one level of a finite supported path under that contract, that the
counted interpreter's run over the whole recognised fragment---extraction, child
check, call, restoration and return---is related to the model's run of the same
term by heap compatibility, with the same result, fault and write trace
(\lean{principal\_counted\_fragment}). A second theorem composes recognition, the
finite-path model correspondence and the counted boundary accounting
(\lean{principal\_supported\_path}), and a closed kernel-checked instance inhabits
it at the recogniser's layout. The closest predecessor, Huisinga's static
uniqueness analysis for a Lean IR model \cite{huisinga}, enforces uniqueness by a
static analysis and leaves soundness and the compiler connection as future work;
here the analysis is a proved relation over an existing IR, and the connection to
the emitted fragment is checked. The guarantee remains relative to entry, layout,
recognition and call premises, and stops at the model heap.

\paragraph*{Three contributions.}
\begin{itemize}
\item \textbf{Complete accounting and its preservation.} An owning-variable support,
a live-cell domain and the roots-plus-edges equation yield the count-one
dichotomy, reject the two-owner countermodel, and make preservation provable:
\lean{supported\_run} takes an accounted state and one supplied slot fact and
concludes a fault-free run of the supported fragment with exclusively flagged
writes and accounting at every state reached. The proof says why: a move
transfers an owner rather than adding one, a single decrement removes one root
together with one count, and a scalar-for-scalar store adds and removes no edge.
\item \textbf{A counted protocol at its accounted boundaries.} The pair's traffic
is neutral at release, the negative controls leave counts elevated, and
restoration's mutate branch is derived rather than assumed; \lean{counted\_nested\_chain}
composes take-out, an admitted child call and restoration into one chain, related
to the model by a cursor-tolerant compatibility relation. The technique is what
survives a correct protocol under which the simple invariant is deliberately
false: count identities inside the window, accounting at its boundaries.
\item \textbf{A checked connection from emitted LCNF to the models.} A recogniser
walks the actual declaration, pinning operation order, arities, operand identities
and branch constructors, and its trace is executed and related to the model. The
flat composed guarantee relates recognised execution, model run and runtime model
at the designated in-place write with no accounting premise; the nested statement
composes the finite-path correspondence, the counted chain and the counted
interpreter's whole-fragment run at one supported level, from an accounted caller
state and the counted child-call contract, with a closed instance discharging
every premise.
\end{itemize}

preservation (\Cref{sec:checker}), the counted protocol (\Cref{sec:protocol}), the
compiler connection (\Cref{sec:correspondence}), the instance and evidence
(\Cref{sec:case}), and the comparison and limits (\Cref{sec:related,sec:limits}).

\section{The running example and the semantic setting}\label{sec:setting}

Lean~4 compiles source through a sequence of IRs. Its last LCNF phase inserts
reference-count operations and the backend emits C; \lean{lean\_is\_exclusive}
tests a stored count against one and a persistence flag. The object here is
single-threaded, and count one with non-persistence is the whole of the test we
model. The development pins the toolchain, the sibling revision and the captured
LCNF artifacts, so every claim names the code it is about. The problem is not to
implement reference counting but to know statically that the count at a particular
write is one; since Lean's source has no linearity, we state the property over the
compiler's code and prove the connection, rather than extend the type system.

\subsection{The update and its ownership traffic}\label{sec:example}
The source is the array case of \lean{Layout5.setAt} in the sibling: take the
element out, check the extracted focus, recurse on it, put the result back.
\begin{lstlisting}
| _, .index i q, y, s =>
    if h : i < s.size then
      match takeOutAt (assertExclusiveArray openSite s) i h (stateDefault _) with
      | ⟨(sib, focus), hbound⟩ =>
        plugAt sib i hbound (setAt q y (assertExclusive structSite focus))
    else s
\end{lstlisting}
The emitted code is the sequence the development names: a \lean{lean\_is\_exclusive}
test for the array, the take-out exchange (\lean{lean\_array\_fget},
\lean{lean\_array\_fset} and the pair allocation), the child check on the extracted
element, the recursive call, and the \lean{lean\_array\_fset} put-back.
\Cref{fig:traffic} draws the same three states throughout the paper: the entry,
where one root and one slot edge account for the two cells; the take-out, where
the temporary pair holds the parent in a field while the caller's handle still
owns it; and the release, where the pair is gone and the two projected handles own
the cells again.

\subsection{Two languages, one accounted subset}
\label{sec:languages}
The checker does not run on Lean source or on LCNF. Its programs are two small
inductive types, interpreted over a model heap and environment; the compiler
connection is a mapping from recognised LCNF to these values.
\begin{lstlisting}
inductive Code where
  | let (x : Var) (v : LetF) (k : Code)
  | inc (x : Var) (n : Nat) (k : Code)
  | dec (x : Var) (n : Nat) (k : Code)
  | check (x : Var) (k : Code)
  | setArr (x : Var) (i : Var) (v : Var) (k : Code)
  | ret (x : Var)

inductive NCode where
  | base (c : Code)
  | takeOut (a i fst snd : Var) (e : Ref) (k : NCode)
  | putBack (a e i result : Var) (k : NCode)
  | callAt (state path x result : Var) (body : NCode) (k : NCode)
  | ret (x : Var)
\end{lstlisting}
A \lean{Code} is the straight-line array-write fragment; an \lean{NCode} adds
extraction, restoration and the recursive call. A \lean{LetF} is one of
\lean{lit n}, \lean{size a}, \lean{isShared x} or \lean{checkAlias x}. Variables
are \lean{Nat}, references are \lean{Nat}, \lean{Val} is a reference, a scalar or
erased, and a \lean{Heap} maps references to objects with a field array, a count
and a persistence flag. \lean{run}/\lean{runN} execute these values and
\lean{check}/\lean{checkN} are the checkers; every soundness theorem is about this
semantics. They are neither Lean source nor LCNF: \lean{projectPrefix} and
\lean{projectNested} walk an LCNF value, \lean{Prefix.toModel} and
\lean{indexModelTerm} read a \lean{Code}/\lean{NCode} off the recognised operands,
and \lean{execAST}/\lean{execNestedAST} execute the recognised trace.

The two languages play different roles and must not be conflated. \lean{Code}
and \lean{NCode} are the checker's \emph{general} language: it contains
increments, multi-count decrements and arbitrary nesting, and the checker accepts
programs that carry no accounting. The theorem-bearing fragment is
\lean{Supported} (\Cref{sec:supported}), an inductively defined subset of
\lean{Code} with extra certificates. Checker acceptance, supported certification,
state validity and the child-call specification are four separate notions; no
result here says that \lean{check c s = some c'} alone preserves accounting.

\section{Complete ownership accounting}\label{sec:accounting}

The model heap, its counts and exclusivity are the semantic side of the
judgement: \lean{Inv} ties the context's multiplicity to the heap count, and
\lean{Exclusive H r} means that \lean{r} is a live, non-persistent cell whose
count is one.

\begin{definition}[The raw invariant]\label{def:inv}
\lean{Inv H env c} equates the heap's stored count with the context's multiplicity
(\lean{rc\_eq}); an owning variable denotes its reference at multiplicity at least
one (\lean{owned}); a borrowed variable also denotes a live cell (\lean{borrow});
a scalar variable denotes a scalar (\lean{scalar}); and no live cell is persistent
(\lean{nonPersistent}).
\end{definition}

\lean{Inv} relates the heap count to the context multiplicity but does not count
the environment's owning variables: \lean{Inv.owned} only requires
$1 \le c.\mathit{mult}\ r$. \lean{bindOwned} preserves \lean{Inv} without changing
\lean{mult}, so two owned variables can denote one count-one cell, and the raw
invariant does not imply physical uniqueness. The kernel countermodel
\lean{alias\_not\_accounted} constructs exactly that state from
\lean{initCtx}, which has one owner and does satisfy \lean{OwnersAccounted}
(\lean{initCtx\_accounted}). \lean{CountFidelity} is not a consequence of
\lean{Inv}; it is a consequence of the relation below.

\begin{definition}[Complete accounting]\label{def:accounted}
\begin{lstlisting}
structure Accounted (support : List Var) (H : Heap) (env : Env) (c : Ctx) : Prop where
  inv              : Inv H env c
  support_nodup    : support.Nodup
  support_sound    : ∀ x, x ∈ support → c.us x = .owned
  support_complete : ∀ x, c.us x = .owned → x ∈ support
  support_bound    : ∀ x, x ∈ support → ∃ r, c.refOf x = some r
  domain           : ∀ r o, H.cells r = some o → r < H.next
  count            : ∀ r, H.rc r = IncomingCount H r + EnvOwnerCount c support r
\end{lstlisting}
\end{definition}

The relation is deliberately redundant, because each field of it is refutable:
a duplicate in the support counts a root twice (\lean{dupSupport\_witness}), an
omitted owner loses one (\lean{omittedOwner\_witness}), and an unbound root has no
denotation to count (\lean{unboundRoot\_witness}). The support is a duplicate-free
enumeration of every owning variable, each entry is bound to a reference, every
live cell lies inside the range the edge count enumerates, and the count equation
holds over two independently computed quantities.

\begin{lstlisting}
def IncomingCount (H : Heap) (r : Ref) : Nat :=
  ((List.range H.next).map fun q =>
    match H.cells q with
    | some o => (o.fields.toList.filter (fun v => v = .ref r)).length
    | none => 0).sum

def EnvOwnerCount (c : Ctx) (vars : List Var) (r : Ref) : Nat :=
  (vars.filter (fun x => c.us x = .owned ∧ c.refOf x = some r)).length

def CountFidelity (H : Heap) (c : Ctx) (vars : List Var) : Prop :=
  ∀ r, H.rc r = IncomingCount H r + EnvOwnerCount c vars r
\end{lstlisting}

\begin{lemma}[Count-one dichotomy]\label{lem:dichotomy}
If \lean{Accounted support H env c} and $H.\mathit{rc}\ r = 1$, then either
$\mathit{EnvOwnerCount}\ c\ \mathit{support}\ r = 1$ and
$\mathit{IncomingCount}\ H\ r = 0$, or
$\mathit{EnvOwnerCount}\ c\ \mathit{support}\ r = 0$ and
$\mathit{IncomingCount}\ H\ r = 1$.
\end{lemma}
\begin{proof}
Read the count equation through \lean{Inv.rc\_eq} (\lean{mult\_eq}) and split the
two natural numbers whose sum is one. \lean{count\_one\_dichotomy} is the
statement.
\end{proof}

\begin{corollary}[Uniqueness at a known root]\label{cor:unique}
If \lean{Accounted support H env c}, $H.\mathit{rc}\ r = 1$, and an owning
variable $x \in \mathit{support}$ has $c.\mathit{refOf}\ x = \mathrm{some}\ r$,
then $x$ is the only owning variable at $r$ and $r$ has no incoming edge;
\lean{at\_most\_one\_owner} states that any two such variables coincide.
\end{corollary}

This is the count-one consequence that gives the integer a meaning, and
\lean{initCtx} establishes the relation at the initializer
(\lean{initCtx\_accounted}). It is a statement about owning variables and heap
edges, not about physical pointers: no representation theorem connects a model
reference to a runtime object.

\section{The checker and flat preservation}\label{sec:checker}

\subsection{The judgement, once}
A context records, for each variable, whether it is owned, borrowed, scalar or
dead, which reference it denotes, and the multiplicity of that reference. The
checker is a total function from a context and a program to a successor context or
failure; a frame stack records open extractions.
\begin{lstlisting}
inductive U where
  | owned | borrow | scalar | dead

structure Ctx where
  us    : Var → U
  refOf : Var → Option Ref
  mult  : Ref → Nat
\end{lstlisting}
\noindent A frame records the array, index and element of an open extraction;
\lean{check : Ctx → Code → Option Ctx} and
\lean{checkNF : Ctx → List Frame → NCode → Option Ctx} are total.

\paragraph*{The judgement.}
The typing judgement $c \vdash s \Rightarrow c'$ is \emph{defined} to hold exactly
when \lean{check c s = some c'}: the context is the type of the program point, and
there is no separate derivability relation to relate to it. The object language is
untyped; there is no type former for a program, and the checker does not infer one
by unification. The judgement is syntax-directed---one rule per constructor, the
context an input, the successor computed by \lean{setUs}, \lean{move},
\lean{bindOwned}, \lean{inc} and \lean{dec}---so there are no metavariables and the
only computation is the context update. \Cref{tab:rules} gives the rules the rest
of the paper uses; the remaining constructors (literal, size, sharing, check,
put-back and return) have the same shape: a usage-and-multiplicity premise, and a
successor computed by those updates, with \lean{ret} refusing a frame it does not
close.

Two consequences matter later. \lean{dec} is affine, not the last drop: its
premise is $n <$ the object's multiplicity, so it consumes a duplicate handle and
leaves the object live. And linearity at the write is the side condition
$\mathit{multOf}\ x = 1$, not the usage tag alone.

\begin{example}[A unique write is accepted, an aliased one refused]
\label{ex:unique}
\begin{lstlisting}
def execSet (x y i v : Var) : Code :=
  .let y (.checkAlias x) (.setArr y i v (.ret y))

def aliasSet (x y i v : Var) : Code :=
  .inc x 1 (execSet x y i v)

#guard (check (initCtx 0) (execSet 0 3 1 2)).isSome
#guard (check (initCtx 0) (aliasSet 0 3 1 2)).isNone
\end{lstlisting}
The alias increments the handle, so the write's multiplicity-one obligation
fails; the same refusal appears at the context level for a heap whose count is
two. This is the static counterpart of the runtime copy: the checker rejects the
program before it can copy.
\end{example}

\subsection{The supported fragment}\label{sec:supported}
\lean{Supported c s} is indexed at the pre-state \lean{c}; each constructor states
the checker's own rule at \lean{c} and its continuation at the checker's
post-state, and carries the certificates the checker cannot see: a fresh alias
target and a fresh scalar-\lean{.let} target. The fragment has eight
constructors; \lean{.inc} is absent and every \lean{.dec} is the single-count form
\lean{.dec x 1}, whose premise \lean{1 < c.mult r} is exactly the checker's.
From \lean{Supported c s} the checker accepts the program
(\lean{supported\_check}), which is what lets a preservation theorem follow a
fault-free run.

The store's slot fact is deliberately not a constructor premise: no context
records which value a cell's selected slot holds, so it is the \lean{StoreSlots}
premise of the preservation theorem instead. \lean{StoreSlots H env s} is a
recursive predicate over the supported program, supplied from the heap and
environment alone (it may not assume the invariant): at the store the run reaches,
the array cell's selected slot holds a scalar, so the in-place write replaces a
value rather than an edge. \lean{storeSlots\_init} discharges it for the
initializer's measured write, and nothing general.

\subsection{Preservation}\label{sec:preservation}
\begin{theorem}[Supported execution preserves accounting]\label{thm:supported-run}
Let \lean{Supported c s}, \lean{Accounted support H env c} and
\lean{StoreSlots H env s}. Then there are $c'$, $H'$, $\mathit{env}'$, $v$ and
$ws$ with \lean{check c s = some c'} and \lean{run s env H = .done H' env' v ws},
such that every write in $ws$ is flagged exclusive,
\lean{Accounted (resultSupport s support) H' env' c'}, and
\lean{AccountedAlong H env c support s}.
\end{theorem}
\begin{lstlisting}
theorem supported_run {c : Ctx} {s : Code} (hs : Supported c s)
    {support : List Var} {H : Heap} {env : Env}
    (hacc : Accounted support H env c) (hslots : StoreSlots H env s) :
    ∃ c' H' env' v ws,
      check c s = some c' ∧
      run s env H = .done H' env' v ws ∧
      (∀ w ∈ ws, w.2 = true) ∧
      Accounted (resultSupport s support) H' env' c' ∧
      AccountedAlong H env c support s
\end{lstlisting}
\lean{AccountedAlong} is a conclusion, never a hypothesis: at each instruction the
relation holds at the interpreter's own post-state, and at each array store the
target is exclusive (\lean{supported\_store\_exclusive} states the store's own pre-
and post-state).

\paragraph*{Proof sketch.}
Induct on the derivation of \lean{Supported c s}, generalising the support, the
heap and the environment; the measure is the syntax of the supported program and
the induction hypothesis is applied to the continuation at the state the step
produces. Each case is a step of \lean{run} followed by the induction hypothesis,
and the content is in three cases.
\emph{Fresh binding} (\lean{bindAlias}): the alias target
takes over the source's owning obligation, and the support variable is renamed by
\lean{replaceVar}; \lean{Accounted.move} shows that \lean{EnvOwnerCount} is
unchanged, because the enumeration follows the handle rather than the name. Freshness
is what makes this a transfer: were the target already an owner, the support would
gain a duplicate and \lean{support\_nodup} would fail. The scalar binders
(\lean{bindLit}, \lean{bindSize}, \lean{bindShared}) use
\lean{Accounted.setScalar}, which adds no owner and no edge.
\emph{Decrement} (\lean{decOne}): the support loses \lean{x}, the heap loses one
count, and \lean{IncomingCount} is unchanged, so both sides of the equation at
$r$ fall by one (\lean{Accounted.decOne}); the multi-count decrement is excluded
precisely because it would release counts that no obligation carried
(\lean{decTwo\_rejected}). \emph{Edge-neutral scalar store} (\lean{setArr}): the
slot fact gives that the selected slot holds a scalar, and the run writes a
scalar, so the set of incoming edges is literally unchanged; the equation is
preserved by \lean{Accounted.setArrInPlace} at the checker's unchanged context,
which is where the write's exclusivity and its trace event are produced. The
remaining cases commute with the induction hypothesis.

\section{Counted protocol and boundary simulation}\label{sec:protocol}

\subsection{The pair and its boundary}
The take-out builds a pair of the parent and the extracted child; the
projections increment both components; freeing the unique pair releases both
edges. At the boundary the counts return to their entry values only because the
pair is freed.
\begin{theorem}[Pair accounting]\label{thm:pair}
Let \lean{WellFormedEntry H p c i}: both components live, non-persistent and at
count one, $p$'s selected slot holding $c$, and the fresh name empty. Let
$B = \mathit{protocol}\ H\ p\ c\ i$ return the fresh name $B_1$ and the heap
$B_2$. Then
\[
B_2.\mathit{rc}\ p = 1,\quad B_2.\mathit{rc}\ c = 1,\quad
B_2.\mathit{cells}\ B_1 = \mathrm{none},
\]
both components are \lean{Heap.Exclusive} in $B_2$, and their counts are $H$'s.
\end{theorem}
\begin{lstlisting}
theorem pair_accounting {H : Heap} {p c : Ref} {i : Nat}
    (hw : WellFormedEntry H p c i) :
    let B := protocol H p c i
    B.2.rc p = 1 ∧ B.2.rc c = 1 ∧ B.2.cells p ≠ none ∧
      B.2.cells c ≠ none ∧ B.2.cells B.1 = none ∧
      Heap.Exclusive B.2 p ∧ Heap.Exclusive B.2 c ∧
      B.2.rc p = H.rc p ∧ B.2.rc c = H.rc c
\end{lstlisting}
The no-free control, \lean{no\_free\_components\_not\_exclusive}, leaves both
components at count two, neither exclusive, and the pair live: the boundary is
produced by the free, not by the projections.

\subsection{The counted call and restoration}
\lean{counted\_takeOut} consumes the array's cell and selected slot plus the
context facts from \lean{checkNF}; it derives the boundary accounting,
\lean{HeapCompat}, the pair's freshness and the cursor advance. The child call is
where the modular boundary sits. \lean{CountedChildCall} adds one field to the
model child-call contract:
\begin{lstlisting}
structure CountedChildCall (Hin Hout : Heap) (env : Env) (ctx : Ctx)
    (state path x : Var) (body : Nested.NCode) (p c : Ref)
    (support : List Var) : Prop where
  call      : PutBack.ChildCall Hin Hout env ctx state path x body p c
  accounted : Accounted support Hout env ctx
\end{lstlisting}
\lean{call} is the boundary the put-back consumes. \lean{accounted} is the
caller's complete accounting at the body's return, and it is an \emph{explicit
premise}: the finite-path induction derives the ordinary \lean{ChildContract} at
every level (\lean{childContracts\_of\_path}) but not this field, because the
ordinary contract does not mention the caller's ownership state. The closed
instance supplies it from the caller's own accounting at the return
(\lean{calledAccounted}). From the call's output state, \lean{counted\_restore}
derives the mutate branch and the accounted post-state, and
\lean{putBack\_exclusive\_of\_wellFormed} concludes \lean{Heap.Exclusive} for both
the parent and the restored child.

\begin{theorem}[Counted chain]\label{thm:chain}
From an accounted caller entry, take-out, an admitted \lean{CountedChildCall} and
restoration compose into one chain: \lean{counted\_nested\_chain} concludes the
final counted state, its accounting, the restoration's \lean{.mutate} disposition,
and \lean{HeapCompat} to \lean{runN}'s state; the restored slot's own equation is
\lean{counted\_nested\_chain\_restoration}.
\end{theorem}

\subsection{Compatibility and the boundary argument}
\begin{definition}[Heap compatibility]\label{def:compat}
\lean{HeapCompat Hc Ha} holds when $Hc$ and $Ha$ hold the same cell at every name
and $Ha.\mathit{next} \le Hc.\mathit{next}$. At the protocol instance the slack is
exactly the pair allocation the counted side performs and the model's take-out does
not; the relation itself permits any slack, and
\lean{HeapCompat.eq\_of\_cursor\_eq} shows that with equal cursors the heaps are
equal, so it is equality of cells up to the counted side's allocation, not a
weakened equivalence.
\end{definition}

The pair-live window is not an accounting failure but a deliberate boundary
abstraction, and the case we exhibit is forced: at the take-out state of
\Cref{fig:traffic}(b), at the context the run's own take-out rule produces, no
support satisfies \lean{Accounted} (\lean{pairPhase\_refused}), because the count
equation reads one $=$ one plus one. The positive control is the boundary, where
the counts match again. Three facts make the window safe. The projections' effect
is exactly the pair's component increment (\lean{incPairComponents\_eq}). The
release is boundary-neutral (\lean{pair\_traffic\_neutral}): the parent's and
child's counts are their entry counts, the child's cell is the entry's, and the
temporary pair is gone. And the suspended parent remains exclusive across the
child call because the child's contract is confined to the child's mutable
footprint rather than because the parent's exclusivity is assumed:
\lean{callAt\_frame\_confined} takes \lean{AnnotationsIn}, checker acceptance, the
return variable, the isolated \lean{Inv} and \lean{TakeOutsOK}, and the
parent/child separation is a \lean{ChildCall.separated} fact used in the path
derivation. Finally the put-back's mutate branch follows from the protocol
boundary and the child-call boundary, not from an assumed final state.

\paragraph*{Proof sketch.}
The protocol argument is a decomposition, not an induction: the five heap-touching
operations are discharged in order, each by a count identity on the heap it
produces, and the composition is \lean{counted\_nested\_chain}. Transfer into the
pair moves the handles and leaves the pair's fields as the edges; projection adds
one root per component; release removes the pair's two edges and nothing else;
the call is suspended at the boundary; restoration reads the child's output state
and writes the slot. Because each identity is stated at the state it produces,
the chain never needs \lean{Accounted} inside the window---only at its ends---and
\lean{HeapCompat} carries the one-cell cursor slack that the allocation leaves
behind.

\section{Recognised-fragment correspondence}\label{sec:correspondence}

\subsection{Recognition, and the flat guarantee}
A source-level discipline is only useful if it survives lowering. The compiler
rewrites programs, inlines helpers and chooses the emitted shape, so the
recogniser walks the actual LCNF value, pinning operation order, arities, operand
identities and branch constructors. \lean{projectPrefix} accepts the flat write,
\lean{projectNested} the \lean{Path.index} arm and \lean{projectPair} the two pair
arms; token-preserving near misses are rejected (eleven at the top level, eleven
on the nested path, fourteen per pair arm), so the correspondence is about the
code we name. No universal rejection theorem is claimed; the claim is scoped to
the accepted grammar and the mutation corpus. \lean{project\_sound} gives
executed/model equality for the abstract prefix, and \lean{execAST\_recognized} is
decoding adequacy: it relates the trace to the model, it is not a semantics.

\begin{theorem}[Flat principal guarantee]\label{thm:principal-write}
Let \lean{projectPrefix code = some p}, \lean{Layout assign p}, the entry invariant
\lean{EntryInv H env (Runner.initCtx root) root client}, the machine/model
agreement \lean{Agrees assign p s env H root i v}, the cell and index facts
$H.\mathit{cells}\ \mathit{root} = \mathrm{some}\ o$ and $i < |o.\mathit{fields}|$,
and a runtime correspondence \lean{Corr H R} with
$R.\mathit{cells}\ \mathit{root} = \mathrm{some}\ o'$. Then the executed prefix's
outcome and the model's run both equal \lean{inPlaceOutcome root i v o H}, and for
some $H'$ the runtime's \lean{setAt} returns \lean{.inPlace H' root} with
\lean{Corr} preserved, the target $root$ and the slot holding the written scalar.
\end{theorem}
\begin{lstlisting}
theorem principal_write
    (hproj : projectPrefix code = some p) (hl : Layout assign p)
    (hEntry : EntryInv H env (Runner.initCtx root) root client)
    (hag : Agrees assign p s env H root i v) (hcell : ...) (hin : i < o.fields.size)
    (hc : Corr H R) (ho' : R.cells root = some o') :
    PrefixOutcome.ofExec assign p (execAST assign p code s) =
        some (inPlaceOutcome root i v o H) ∧
      PrefixOutcome.ofModel (Ownership.run (Prefix.toModel assign p) env H) =
        inPlaceOutcome root i v o H ∧
      ∃ H', Runtime.setAt R root i (.scalar v) = some (.inPlace H' root) ∧ ...
\end{lstlisting}
The proof is the conjunction of \lean{recognized\_write\_in\_place} and
\lean{Runtime.setAt\_inPlace\_of\_entryInv}, and it takes no accounting premise.
\lean{Accounted} is consumed at the initializer by \lean{principal\_accounted},
which yields \lean{OwnersAccounted}, \lean{CountFidelity} and the count-one
dichotomy. \lean{Prefix.toModel\_supported} puts the certified flat model in the
counted fragment, so \lean{supported\_run} applies once \lean{StoreSlots} is
supplied---at \lean{execSet} by \lean{storeSlots\_init}, not for a general
$p.\mathit{toModel}$. The two results are adjacent, not one theorem.

\subsection{The finite path and the counted fragment}
The model nests take-out, call and put-back per level. For a finite level path the
ordinary child contract is derived at every level: \lean{childContracts\_of\_path}
takes the level list and a supplied path contract whose one function-level
ingredient is the leaf computation (agreement, checker acceptance, exit variable,
count-freedom, annotation), the rest being the level's slot, environment, context,
shape and heap facts, and yields the ordinary
\lean{ChildContract} at each level, whose body is the remaining levels'
\lean{Path.build}; \lean{index\_path\_simulates\_model} concludes that the executed
nested prefix's \lean{NestedOutcome} is the model run of
\lean{Path.build path value body (l :: rest)}, completing with an all-exclusive
trace under the recogniser's verdict, layout, level match, agreement and path
contract. The counted call is not a consequence of that induction
(\Cref{sec:protocol}). Two bounds are recorded rather than hidden: the flat
environment cannot express the emitted per-invocation \lean{oproj[1]} index, so a
deeper level that re-indexes by re-projecting the continuation is outside the
model; and the emitted callee is not captured---\lean{execNested}'s call rule runs
the admitted model body with only the call's state, path and value (N10).

\begin{theorem}[Counted fragment correspondence]\label{thm:principal-fragment}
Let the recogniser accept the declared shape (\lean{projectNested} yielding $p$),
let the layout, the machine-to-model agreement \lean{NestedAgrees} and the level
match hold at one level of a finite path, let the client's path contract and the
caller's complete accounting \lean{Accounted support H mEnv c} hold, and let the
counted child call
be supplied at the protocol's boundary with the caller's accounting at the body's
return. Then, writing $H_f$ for the counted final heap:
\begin{enumerate}
\item \lean{execCountedAST} runs the whole recognised fragment
$p.\mathit{fragment}$ from the entry machine to a completed state with heap $H_f$,
result the caller's array handle, restored binder holding that handle, and write
trace the entry trace followed by the child's;
\item the model run of \lean{Path.build path value body (l :: rest)} completes with
that handle and an all-exclusive trace;
\item the counted and model outcomes are \lean{NestedOutcome.Compat}: they agree
by \lean{HeapCompat} and literally on the result, the fault and the write trace;
\item the accounting holds at the protocol's boundary over the extended support,
and at $H_f$ over the support the call's result binding and the restoration's
renamings determine;
\item at the boundary the fresh cursor cell is empty, the cursor advances by one,
both components are exclusive, and the boundary heap is heap-compatible with the
abstract take-out heap; at the call's output heap the put-back selects
\lean{mutate}, writes the child into the parent's selected slot, and changes no
other cell.
\end{enumerate}
\end{theorem}

\paragraph*{Proof sketch.}
The measure is the decomposition of the fragment, not a recursion on syntax.
Recognition fixes operand identities and operation order, so the counted
interpreter's fragment is a fixed sequence; \lean{fragment\_decomp} splits it at
the release-terminated prefix \lean{countedPrefix}---a syntactic split, not a
numeric cutoff---giving \lean{countedSuffix} as the rest. On the prefix,
\lean{execCounted\_protocol\_boundary} reports the protocol boundary heap, agrees
with \lean{execNested} on the non-heap fields including the write trace, and
relates the two heaps by \lean{HeapCompat}. On the suffix,
\lean{execCounted\_full\_fragment} runs the child assertion, the call at the
boundary state, the restoration at the call's output heap and the return. The
call is consumed where the interpreter reaches it, so the supplied contract is
used at the actual call-entry state rather than at a reconstruction of it, and
the restoration's mutate branch is derived at the actual output state. The two
halves compose to \lean{NestedOutcome.Compat}, and because the entry point is
\lean{execCountedAST}, the recogniser's verdict is spent by the theorem rather
than assumed by its statement.

\section{The instance, the case study and the artifact}\label{sec:case}

\subsection{A worked instance}\label{sec:case-family}
The instance is a family. For an outer slot $i$, a leaf slot $j$ and a value $w$,
the entry holds two live, non-persistent cells at count one: the parent array at
reference $0$ carries the child handle in slot $i$ and scalars elsewhere, the
child array at reference $1$ is all scalars, and reference $2$ is the fresh name.
The child body is one designated write that stores $w$ in the child's slot $j$ and
returns the child handle. Four declarations carry the family, for every $i < n$
and $j < n$: \lean{entryAccounted} accounts the entry; \lean{boundary\_cells} and
\lean{boundary\_accounted} report the protocol boundary and its accounting;
\lean{countedBoundaryCall} discharges the counted child-call contract; and
\lean{family\_chain} states the whole \lean{counted\_nested\_chain} conclusion at
that data, with \lean{family\_chain\_two} its length-two instance. The bound is the
only length fact these proofs use: the slot facts are
\lean{Array.getElem?\_setIfInBounds\_self\_of\_lt}, and the count equation at the
parent's and the child's own references comes from
\lean{IncomingCount\_baseHeap}, \lean{IncomingCount\_set\_fill} and
\lean{IncomingCount\_set\_fill\_ne} on the all-scalar array.

Take $i = 0$, $j = 1$ and $w = 7$. Before the take-out the parent's slot $0$
holds \lean{.ref 1} and its slot $1$ a scalar; after it, slot $0$ holds the
placeholder \lean{.scalar 0}, the temporary pair has been allocated at name $2$
and released, and the cursor stands at $3$. The leaf then stores
\lean{.scalar 7} in the child's slot $1$, and the restoration refills the parent's
slot $0$ with \lean{.ref 1}. Three facts are separate and none implies the others:
the restored array is functionally the model's own \lean{set}; the counts are back
to one at both components with the pair gone; and the restoration took the
\lean{.mutate} branch because the parent is exclusive at the call's output state,
not because the counts happen to be unchanged. The final heap and the abstract
run's heap are related by \lean{HeapCompat}, not equality: the counted run's
cursor is one higher, the residue of the temporary pair.

\lean{principal\_instance} inhabits \lean{principal\_supported\_path} at the
recogniser's layout on a reified transcription of the captured declaration, with
every premise supplied, and \lean{counted\_fragment\_instance} inhabits
\lean{principal\_counted\_fragment} at the same data; both are closed
existentials whose \lean{\#print axioms} record is the trusted footprint. The
instance discharges \lean{CountedChildCall} through \lean{calledAccounted}, which
is the caller's own accounting at the body's return rather than an extra
assumption: no theorem in the development derives that field from the path
induction.

\subsection{What the mechanisation taught}
Four lessons transfer to anyone building another analysis of this kind. First,
the tempting invariant---count equals multiplicity---is too weak, and the
countermodel \lean{alias\_not\_accounted} exposes it: the missing quantity is the
environment's owning variables, not the heap's edges. Second, support and domain
coverage are not bureaucracy: without the domain field the edge count is taken
over a range that need not contain every live cell, so a cell's stored count and
the enumerated edges can disagree. Third, the simple accounted relation cannot hold inside a correct
temporary-alias protocol, and no amount of invariant engineering fixes that: the
pair legitimately duplicates a reference before any count is incremented, so the
right response is boundary simulation with internal count identities, not a
stronger invariant that the protocol would have to satisfy. Fourth, allocator
progress prevents plain equality, so correspondence between a counted run and an
abstract one needs an explicit cursor slack; \lean{HeapCompat} is that slack made
a relation, and it degenerates to equality when the cursors agree. Finally, some
restrictions follow from the chosen representation---the flat environment cannot
express a re-projected index---while others are unimplemented features: general
increments are excluded because no supported obligation carries them, whereas
concurrency and persistence flags are simply outside the fragment.

\section{Related work}\label{sec:related}

Huisinga's 2023 thesis \cite{huisinga} is the closest predecessor and the
comparison is exact. It analyses a model of Lean's IR, enforces uniqueness through
a static analysis, and studies that analysis's checker; uniqueness there is a
property of the analysis, not of the runtime count; it has no compiler link; and
its soundness argument and compiler integration are stated as future work. The
difference is not that our proofs are machine checked---theirs could be
too---but what is connected: here a count-one checker is proved against a model
heap with an explicit roots-and-edges accounting, that result is composed with a
transform of the recognised emitted prefix and with a second runtime model at the
flat write, and the extraction protocol is isolated at proved accounted
boundaries. This is not a claim to the first static uniqueness analysis for Lean.

Perceus \cite{perceus} and Counting Immutable Beans \cite{countingbeans} are
count-insertion and reuse transformations: an ownership pass inserts counts and
reuse tokens, the runtime maintains them, and the correctness argument is about
the transformation's semantics preservation and its allocation behaviour. They do
not answer the question asked here, which is when a count of one is justified at a
given write in code that already exists; \lean{Accounted} is a specification of
that justification, and this paper proves it for a restricted fragment rather than
proving a transformation. Linear Haskell \cite{linearhaskell} makes linearity a
source-level type property through linear arrows and multiplicities, and Clean's
uniqueness typing \cite{uniqueness} is uniqueness rather than linearity; neither
is a checker over an existing compiler IR, and neither is connected to emitted
code. Lean's \lean{Array.markLinear} \cite{marklinear} is dynamic: it can copy an
array to establish uniqueness and, with \lean{LEAN\_ABORT\_ON\_NONLINEAR}, abort
on a later nonlinear use. Translation validation \cite{translationvalidation}
checks one compiler run rather than a static discipline, and verified compilation
\cite{compcert,cakeml} proves a compiler correct for its source language; both are
different in kind from a checker over a fragment of an existing backend's input.

\begin{nonclaim}
The C semantics of the primitives, replay-to-backend identity, address identity,
free and cascade, and the source correspondence are neither formalised nor
attempted. The emitted recursive callee and continuation (N10) are not captured,
and the flat environment cannot express the per-invocation index, so a deeper
level that re-projects its index is outside the model. The leaf body and several
heap-shape facts are supplied. Persistence, concurrency and callbacks are outside
the fragment, and the nested linked runtime is not measured.

The accounting layer is not a consequence of \lean{Inv}: \lean{OwnersAccounted}
has a kernel countermodel, and the checker's certificates are carried by
\lean{Supported}, whose fragment excludes \lean{.inc} and admits only
\lean{.dec x 1}. \lean{StoreSlots} is supplied, and \lean{storeSlots\_init}
covers only the initializer's measured write. \lean{principal\_write} takes no
accounting premise and concludes none; \lean{principal\_supported\_path} takes the
caller's accounting and the counted child call and concludes accounting at the
counted boundary and at the restored state; no statement carries either relation
to a physical counted reference, and no step-by-step agreement between the two
interpreters inside the pair-live window is claimed. The nested trace omits
extraction and restoration stores---neither interpreter records them as
\lean{Write} records---but each target cell is proved exclusive
(\lean{checkN\_extraction\_exclusive\_of\_entryInv}), a fact about the store's
target rather than a trace event, and not a silent absence. Whole-path
non-growth outside the root's mutable footprint is not concluded; it needs the
leaf's write account. ``In place'' throughout is the modelled disposition: the
array operation neither copies nor allocates under the contracts these statements
take, and it is not a zero-allocation claim for the protocol, whose take-out
allocates the pair. The pair-arm correspondence with \lean{Ownership.Pair.runP} is
a named next step.
\end{nonclaim}

\paragraph*{Conclusion.}
A count-one discipline can be recovered for an existing compiler IR without
changing the language, provided the accounting is complete rather than local, and
provided the emitted protocol is treated as a boundary phenomenon rather than an
invariant. That is what this paper establishes: a proved relation between owning
roots and incoming edges with the uniqueness consequence that makes a stored count
one meaningful; preservation for a restricted flat fragment, with the slot fact
isolated as the one premise the checker cannot see; a counted extraction, call and
restoration protocol proved at its accounted boundaries, with the in-place
restoration branch derived at the call's output state; and, for the full counted
fragment at one level of a finite supported path, a checked correspondence to the
model's run---heap-compatible, with the same result, fault and write trace---under
an explicit counted child-call contract that the closed instance discharges. The
result buys a checked count one for that fragment, not a type system and not a
physical count. Next come the C semantics, replay and address identity, free and
cascade, and the emitted callee. Soundness is proved; completeness is not claimed.
