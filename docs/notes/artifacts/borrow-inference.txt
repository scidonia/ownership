## Inferred signatures of the replayed declarations

def _private.Scidonia.FracPerm.StateVar.Layout5.0.Scidonia.FracPerm.StateVar.Layout5.setAt._redArg x.1 @&x.2 x.3 : tobj

def _private.Scidonia.FracPerm.StateVar.Layout5.0.Scidonia.FracPerm.StateVar.Layout5.takeOut._redArg s @&i d : obj

def _private.Scidonia.FracPerm.Structured.Executor.0.Scidonia.FracPerm.Structured.execP._redArg a x.1 : tobj

`@&` marks a borrowed parameter: the callee reads it without taking ownership.
An unmarked parameter is owned: the compiler decided the callee needs ownership,
i.e. the value is consumed or used non-linearly and the caller's count is
transferred (or an `inc` is inserted at the call site).

- `setAt`: the path (`x.1`) is owned, the replacement value (`x.2`, the
  `State (At p)` argument) is borrowed, and the state (`x.3`) is owned.
- `takeOut`: array owned, index borrowed, default owned.
- `execP`: array owned, tree owned.

## Limit

The borrow inference for the private `setAt`, `takeOut` and `execP` declarations
ran when the pinned sibling's module was compiled into its olean. The replay in
these scripts starts after `saveMono` and re-runs the pass on declarations that
already carry the inferred annotations; the pass therefore does not re-emit the
"own" lines for them. What is recorded for the pinned declarations is the
resulting signature, which is the compiler's decision, not a re-derivation.

This is a compiler decision log, not a linearity certificate. It reports no
pass-rate: an owned parameter is a deliberate ownership decision (the value is
consumed or non-linear at the callee), not a failure. The model's linearity
(`Scidonia.FracPerm`) and the runtime's exclusivity (`inplace`) are separate
properties; see `docs/notes/OWNERSHIP_RUNTIME_EVIDENCE.md`.
